## 1. 部署前检查

### 1.1 有没有 Docker

```bash
docker version
```

**期望**：能同时看到 `Client:` 和 `Server:` 两段，Server 段 `Version: 20.10` 或更高。

**不对怎么办**

| 现象 | 处理 |
| --- | --- |
| `command not found` | 没装 Docker，先装：`curl -fsSL https://get.docker.com \| sh`，再 `systemctl enable --now docker` |
| 只有 `Client:`，`Server:` 段报 `Cannot connect to the Docker daemon` | 服务没起：`systemctl start docker`；或当前用户没权限：命令前加 `sudo`，或 `usermod -aG docker $USER` 后重新登录 |
| 版本低于 20.10 | 能跑，但建议升级；旧版 libseccomp 需要 compose 里那行 `seccomp:unconfined`（本包已带） |

> 如果这台机器上有别的 Docker 安装位置（比如 `/opt/kube/bin/docker`），先 `which docker` 确认，
> 后面所有 `docker` / `docker compose` 都换成对应绝对路径即可。

### 1.2 有没有 compose

```bash
docker compose version || docker-compose version
```

**期望**：任意一条能打印版本号就行。两条都失败时用 `docker compose` 就换 `docker-compose`（老版本）
或服务器上的绝对路径（如 `/opt/kube/bin/docker-compose`）。

### 1.3 端口空不空

```bash
ss -lntp | grep 8088 || echo "8088 空闲"
```

**期望**：输出 `8088 空闲`。

**不对怎么办**：8088 被占用了，记下占用进程（`ss -lntp | grep 8088` 输出里的 `users:(("xxx",pid=1234))`），
然后**改端口**（第 4.3 节），不要硬抢。

### 1.4 磁盘够不够

```bash
df -h .
```

**期望**：可用空间 ≥ 5 GB（镜像 132 MB + 解压后约 300 MB + 数据）。

**不对怎么办**：把部署目录换到空间大的盘（`FB_DATA` 指过去，见第 4.1 节）。

### 1.5 架构对不对

```bash
uname -m
```

**期望**：`x86_64`。

**不对怎么办**：`aarch64` / `arm64`（ARM 机器）跑不了这个 amd64 镜像，见第 10.7 节。

## 2. 第一步：把文件送到机器上

### 2.1 要传什么

整个目录 7 个文件（`.env` 是隐藏文件，图形工具里记得开“显示隐藏文件”）：

```
focalboard/
├── docker-compose.yml
├── .env
├── conf/quotes.txt
├── config.json
├── Dockerfile
├── focalboard-lan-8.0.0-leave.tar.gz
└── 镜像使用说明.md
```

### 2.2 建目录

在**目标机器**上：

```bash
mkdir -p /root/focalboard/conf
```

### 2.3 上传（在你有文件的那台电脑上执行）

Linux / macOS / Windows PowerShell 都自带 `scp`：

```bash
cd 本地目录
scp -P 22 docker-compose.yml .env config.json Dockerfile \
    root@服务器IP:/root/focalboard/
scp -P 22 conf/quotes.txt        root@服务器IP:/root/focalboard/conf/
scp -P 22 focalboard-lan-8.0.0-leave.tar.gz root@服务器IP:/root/focalboard/
```

> `-P` 是**端口**（大写）。默认 22 就删掉这一段。文件大的话 60 MB 大概几十秒。
> 图形界面用 WinSCP / FileZilla / MobaXterm 拖过去也行，注意 **`.env` 要以“显示隐藏文件”方式传**，别漏。

### 2.4 校验传输完整性（重要，别跳）

在**目标机器**上：

```bash
cd /root/focalboard
sha256sum focalboard-lan-8.0.0-leave.tar.gz
```

**期望**：`0daf6b7668c731d505479370e1a6c32c9e2b7486e8d678b56773518542524209`

**不对怎么办**：说明传输损坏（大文件走网络常见），**重新传一次**。校验不过就别往下走，
否则 `docker load` 会报 `unexpected EOF` 或干脆卡住。

顺便确认隐藏文件在：

```bash
ls -la
```

**期望**：列表里能看到 `.env`（1.1 KB 左右）。

## 3. 第二步：导入镜像

```bash
cd /root/focalboard
docker load -i focalboard-lan-8.0.0-leave.tar.gz
```

**期望输出**（一行）：

```
Loaded image: focalboard-lan:8.0.0-leave
Loaded image: focalboard-lan:8.0.0
```

> 归档里带了**两个 tag**（`-leave` 和 `8.0.0`，指向同一个镜像），所以打印两行。
> compose 用的是 `-leave`；`8.0.0` 这个 tag 留着兼容老 compose 文件。

确认一下：

```bash
docker images | grep focalboard
```

**期望**：

```
focalboard-lan     8.0.0          c3ca048ea0a8   132MB
focalboard-lan     8.0.0-leave    c3ca048ea0a8   132MB
```

**不对怎么办**

| 报错 | 原因 / 处理 |
| --- | --- |
| `open focalboard-lan-8.0.0-leave.tar.gz: no such file or directory` | 目录不对或文件名打错，`ls` 看一眼 |
| `unexpected EOF` | 归档损坏，回第 2.4 节重新传 |
| `no space left on device` | 磁盘满，`df -h` 看是 `/var/lib/docker` 所在的盘；清空间或改 Docker 数据目录 |
| `permission denied` | 非 root 用户，命令加 `sudo`，或 `usermod -aG docker $USER` 后重新登录 |

> 镜像导入是**一次性**的，之后再部署不用重复 load（升级到新版本时才需要）。

## 4. 第三步：改配置（3 处必改）

配置全在 `docker-compose.yml` 的 `environment:` 和 `.env` 里，**不用碰 `config.json`**（那个文件已经不用了，只作对照）。

### 4.1 必改 ①：数据放哪（`.env`）

```bash
vi /root/focalboard/.env
```

文件末尾只有一行有效：

```ini
FB_DATA=./data
```

三选一，**只改这一行**：

| 选哪个 | 写什么 | 什么时候选 |
| --- | --- | --- |
| A（默认） | `FB_DATA=./data` | 数据就放在 `/root/focalboard/data`，备份时拷这个目录最直观 |
| B | `FB_DATA=focalboard_data` | 不想让数据占项目目录，Linux 下 SQLite 读写最快 |
| C | `FB_DATA=/data/focalboard` | 数据要单独放一块大盘；**先建目录**：`mkdir -p /data/focalboard` |

> 不要自己去 `docker-compose.yml` 里再加一条数据挂载行。实测（docker 20.10 + compose v2.34）
> **加两条不会报错，而是后者静默覆盖前者**——容器照样 `Up`，但数据只落在后写的那个目录，
> 前面那个目录永远是空的。表现就是“我改了挂载位置，数据却没跟过去”，很难查。
> 只留 `.env` 一个开关，就是为了避开这种静默覆盖。

> `FB_DATA=` **留空**也不会出错：`${FB_DATA:-./data}` 里的 `:-` 表示空值按未设置处理，
> 自动回落到 `./data`（已实测）。

### 4.2 必改 ②：对外访问地址（`FOCALBOARD_SERVERROOT`）

```bash
vi /root/focalboard/docker-compose.yml
```

找到这一行：

```yaml
FOCALBOARD_SERVERROOT: "http://localhost:8088"
```

改成**别人访问时用的地址**：

| 场景 | 改成 |
| --- | --- |
| 只在服务器本机用 | 不用改，保持 `http://localhost:8088` |
| 局域网同事访问 | `http://192.168.1.50:8088`（换成这台机器的内网 IP，`ip a` 或 `hostname -I` 查） |
| 有域名 / 走反代 | `https://board.example.com`（不带端口，见第 7.4 节） |

> 这个值会用在**服务端生成的链接**里（比如飞书消息里的“打开”按钮）。填 `localhost` 的话，
> 别人点开就是你自己的电脑，打不开。**这是最容易漏的一步。**

### 4.3 按需改③：端口

默认 `8088`，一般不用动。确实要换（8088 被占 / 想用 80）：

要改**两处**，必须一致：

```yaml
    ports:
      - "8088:8088"          # ← 左边改宿主机端口，右边是容器端口
...
      FOCALBOARD_PORT: "8088"  # ← 这个跟着右边走
```

例：改成宿主机的 80 端口 → `ports: - "80:8088"`，`FOCALBOARD_PORT` **保持 `8088` 不变**
（容器里还是监听 8088，只是外面映射到 80）。
例：容器内也换 → `ports: - "9000:9000"` 且 `FOCALBOARD_PORT: "9000"`，两处同时改。

> 只改一处 = 容器起来了但页面打不开，或者端口映射错位。

### 4.4 可选：其余配置

到期提醒推送飞书、登录有效期、匿名统计等 22 个字段全在 `environment:` 里，每行上方都有中文注释，
按需改即可（完整对照表见附录 A）。**暂时不改完全能用。**

改完先验一遍语法，不启动：

```bash
cd /root/focalboard
docker compose config -q && echo 配置OK
```

**期望**：打印 `配置OK`，没有任何 yaml 报错。报错信息见第 9.1 节。

## 6. 第五步：验收

按顺序做完这 6 项，就算部署成功。

### 6.1 服务在响应

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8088/
```

**期望**：`200`（其它值看第 9.3 节）

### 6.2 配置真的生效了

```bash
docker logs focalboard-lan 2>&1 | grep -oE 'Port:[0-9]+|TopBarEnabled:[a-z]+|SessionExpireTime:[0-9]+|TopBarQuotesFile:[^ ]+' | head -4
```

**期望**（4 行，顺序可能略有出入，值是本包默认）：

```
Port:8088
SessionExpireTime:2592000
TopBarEnabled:true
TopBarQuotesFile:/opt/focalboard/conf/quotes.txt}
```

（结尾那个 `}` 是日志格式带的，不用管。）

> 服务端启动时会把整份配置打进日志，这是核对环境变量有没有生效最直接的办法。
> 如果 `Port` 跟你改的对不上，说明 `FOCALBOARD_PORT` 没生效或被 `.env` 覆盖了。

### 6.3 数据落到了你选的位置

方案 A（默认）时：

```bash
ls -l /root/focalboard/data
```

**期望**：出现 `focalboard.db` 和 `files/`。方案 B 看 `docker volume ls | grep focalboard`，
方案 C 看 `ls /data/focalboard`。

### 6.4 语录挂进去了

```bash
docker exec focalboard-lan head -3 /opt/focalboard/conf/quotes.txt
```

**期望**：打印出 `# Focalboard 看板顶部提示栏 · 语录文件` 等注释行。
如果报 `No such file or directory`，说明 `conf/` 没传到 compose 同级目录。

### 6.5 浏览器注册管理员

浏览器打开 `http://服务器IP:8088`（服务器本机用 `http://localhost:8088`）。

1. 首次进入是**注册页**，填邮箱 + 密码 → 创建第一个账号（自动成为系统管理员）
2. 登录后进入工作区，看到「新建看板」/ 空白工作区

**期望**：注册后**直接进得去**，不会卡在“加入看板”弹窗。
（第三版专门修了这个问题：session 时间读成 0 + 管理员缺成员记录；本包是第四版，继续带着这个修复，见附录 D。）

### 6.6 顶栏语录看得见

登录后在任意看板里，顶部会显示一行提示语 + 一句随机语录（本包已打开该功能）。

**期望**：看到类似「今天不卷，明天再说。🐟」的句子，换几个看板会变。

> 没看到？先确认 `TopBarEnabled:true`（6.2 步），再看 6.4 步的语录文件在不在。
> 顶栏只在**看板页面内**显示，工作区首页不一定有。

六项都对 → **部署完成**，可以开始建看板了。

## 7. 第六步：让外面能访问

本机 `curl` 通了不代表别人能打开——还有防火墙这一关。

### 7.1 本机防火墙

先判断这台机器到底有没有开防火墙——**没开就不用放行，直接跳过本节**：

```bash
firewall-cmd --state 2>/dev/null || ufw status 2>/dev/null | head -3
```

| 输出 | 含义 | 要不要放行 |
| --- | --- | --- |
| `not running` | 装了 firewalld 但没启动 | **不用** |
| `running` | firewalld 在跑 | 要，见下 |
| `Status: inactive` | 装了 ufw 但没启用 | **不用** |
| `Status: active` | ufw 在跑 | 要，见下 |
| `command not found` / 两条都无输出 | 没装防火墙 | **不用** |

确认真在跑，再按发行版放行：

```bash
# Ubuntu / Debian（ufw）
ufw allow 8088/tcp

# CentOS / Rocky / Alma（firewalld）
firewall-cmd --add-port=8088/tcp --permanent && firewall-cmd --reload
```

### 7.2 云服务器安全组

阿里云 / 腾讯云 / 华为云都要在控制台**安全组入方向**放行 8088（或你改的端口），
这一步在机器里怎么改都没用，必须去控制台点。

### 7.3 从另一台机器验证

在你自己的电脑上（不是服务器）：

```bash
curl -I http://服务器IP:8088
```

**期望**：`HTTP/1.1 200 OK`。

**不对怎么办**：本机通、外面不通 → 一定是 7.1 或 7.2 没放行；
或者 `FOCALBOARD_LOCALONLY` 被改成了 `"true"`（那样只允许本机访问）。

### 7.4 可选：Nginx 反代 + HTTPS（有域名时）

```nginx
server {
    listen 80;
    server_name board.example.com;

    location / {
        proxy_pass         http://127.0.0.1:8088;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        # 附件上传
        client_max_body_size 50m;
        # WebSocket（看板实时协作要用）
        proxy_set_header   Upgrade           $http_upgrade;
        proxy_set_header   Connection        "upgrade";
    }
}
```

配好后两件事一起做，否则链接会错：

1. `FOCALBOARD_SERVERROOT` 改成 `https://board.example.com`
2. `ports` 改成只绑本机：`- "127.0.0.1:8088:8088"`（不再对外直接暴露）

HTTPS 证书用 certbot：`certbot --nginx -d board.example.com`。

## 8. 日常运维

### 8.1 常用命令

```bash
cd /root/focalboard

docker compose ps                     # 状态
docker compose logs -f --tail 100     # 跟日志（Ctrl+C 退出）
docker compose restart                # 重启
docker compose stop                   # 停止（容器保留）
docker compose up -d                  # 启动
docker compose down                   # 停止并删除容器（数据保留）
```

开机自启已内置（`restart: unless-stopped`），**服务器重启后容器会自动起来**，不用管。
只有你手动 `docker compose stop` 过的，才需要手动 `up -d`。

### 8.2 改配置

```bash
vi docker-compose.yml     # 或 .env
docker compose up -d      # 一条命令生效（docker 检测到配置变了会自动重建容器）
```

改语录**不用**重启：直接编辑 `conf/quotes.txt`，存盘 → 刷新网页就变。

### 8.3 备份

**方案 A（`./data`）**

```bash
cd /root/focalboard
docker compose stop                             # 先停，保证 sqlite 文件一致
tar czf ~/focalboard-backup-$(date +%F).tgz data conf
docker compose start
```

**方案 B（命名卷）**

```bash
docker compose stop
docker run --rm -v focalboard_data:/d -v ~:/b busybox tar czf /b/focalboard-data-$(date +%F).tgz -C /d .
docker compose start
```

**方案 C（绝对路径）**：同 A，把 `data` 换成 `/data/focalboard`。

> 建议加个定时任务，每天凌晨备份一次（`crontab -e`）：
> `0 3 * * * cd /root/focalboard && docker compose stop && tar czf /root/backup/fb-$(date +\%F).tgz data && docker compose start`

### 8.4 恢复

```bash
cd /root/focalboard
docker compose down
rm -rf data && tar xzf ~/focalboard-backup-2026-10-24.tgz     # 恢复 data/ 与 conf/
docker compose up -d
```

### 8.5 升级到新版本

```bash
docker load -i focalboard-lan-8.0.0-leave.tar.gz    # 导入新包（同名 tag 会覆盖）
cd /root/focalboard
docker compose up -d                          # 自动重建容器，用上新镜像
docker logs --tail 20 focalboard-lan          # 确认起来了
```

**数据不受影响**，`data/` 原地不动。`docker-compose.yml` / `.env` 一般不用改。

### 8.6 回滚

新版本有问题时：

```bash
docker load -i focalboard-lan-8.0.0-v2.tar.gz   # 导回旧版本归档（服务器 /root/build 里有）
docker compose up -d
```

如果数据库结构被新版本升过、旧版本读不了，再配合 8.4 恢复对应时间的备份。

**注意**：归档里的 tag 是写死的（第四版带 `8.0.0-leave` + `8.0.0`，第三版只有 `8.0.0`），`docker load` 会**直接覆盖同名 tag**，
不会并存。所以回滚/再升级都是“重新 load 另一个包”，不需要 `docker tag` 或停止容器。

这条路径已实测走过一遍（服务器上 `load v2 → load v3`）：


## 9. 故障排查

> 镜像基于 debian slim，**里面没有 `curl` / `wget` / `ss` / `netstat`**（这是精简镜像的正常状态，不是坏了）。
> 所以下面探测容器内部一律用 `docker exec focalboard-lan bash -c 'echo > /dev/tcp/...'`，
> 或者干脆在宿主机上用 `curl` 打映射出来的端口。

### 9.1 配置 / 启动报错：先跑 `docker compose config`

```bash
cd /root/focalboard
docker compose config          # 有错会指到行号
docker compose config -q && echo 配置OK
```

**下表每行都是在服务器上故意写坏、复现出来的原文**（docker 20.10.1 + compose v2.34.0），
报错对不上表就拿原文去搜，别凭猜测改：

| 报错原文 | 真实原因 | 处理 |
| --- | --- | --- |
| `yaml: line 38: found character that cannot start any token` | 用了 **Tab** 缩进（`environment:` 下一级必须是 6 个空格） | `grep -Pn '\t' docker-compose.yml` 找出来，全换成空格 |
| `invalid interpolation format for services.focalboard.volumes.[].` | 写成了 `${FB_DATA:./data}`，少了减号，正确是 `${FB_DATA:-./data}` | 别动 yml 这行，只改 `.env` 的值 |
| `service "focalboard" refers to undefined volume focalboard_data: invalid compose project` | 用了命名卷（`FB_DATA=focalboard_data`）却把文件末尾 `volumes:` 段删了 | 恢复末尾那三行 `volumes:` / `focalboard_data:` / `name: focalboard_data` |
| `Bind for 0.0.0.0:8088 failed: port is already allocated` | 8088 已被占用 | 按 4.3 换端口，或腾出端口 |
| `Error response from daemon: Get https://registry-1.docker.io/v2/ ... Client.Timeout` | 本机没有这个 tag，compose 去外网拉，服务器不通外网 | tag 写错了（compose 里应为 `focalboard-lan:8.0.0-leave`），或第 3 步 `docker load` 没做 |

> 判断顺序：先看最后一行是不是 `invalid compose project`（配置结构问题），
> 是 `Error response from daemon` 就是 Docker 层（端口 / 镜像 / 挂载），
> 是 `yaml: line N` 就是文本格式问题。

#### 三个“以为是 yaml 坏了”、实测却不是的坑

这三个我都专门写坏试过，结论和常见说法不一样：

| 常见说法 | 实测结果（本机 compose v2.34） | 真实影响 |
| --- | --- | --- |
| 文件带 BOM 会导致起不来 | **能正常解析，不报错** | 老版 compose v1 才报 `unexpected character`；本机不受影响，但仍建议存无 BOM 更保险 |
| 两条数据挂载指向同一路径会报 `Duplicate mount point` | **不报错**，后者静默覆盖前者，容器照常 `Up` | 数据只落在后写的目录，前一个目录永远空的——“换了挂载位置数据没跟过去”就是这个 |
| 字段名拼错会报 `Additional property ... is not allowed` | **不报错**，未知键直接忽略 | 等于“配了不生效”，比报错难查十倍（环境变量名拼错同理，见附录 A） |

**结论**：真正让容器起不来的，基本就是 9.1 表里前两行（Tab / 插值）和“命名卷没声明”。
剩下那些“静默失效”的坑不会给你报错，只会给你一个行为不对的系统。

### 9.2 容器起来就退出

```bash
docker compose ps                                              # STATUS: Exited (1) / Restarting
docker inspect focalboard-lan --format '{{.State.ExitCode}}'    # 1 = 启动期致命错误
docker logs --tail 50 focalboard-lan
```

退出码 1 时日志里一定有一行 `fatal`，**那一行就是真因**，前面那行 `error ... Database Ping failed` 是它的原因。实测过的情况：

| 日志关键行（原文） | 原因 | 处理 |
| --- | --- | --- |
| `fatal ... server.NewStore ERROR ... error="file is not a database"` | `focalboard.db` 被写坏（不是有效 sqlite 文件） | 用 8.4 恢复备份；没备份只能删掉该文件让它重建（**数据清空**） |
| `error="unable to open database file: no such file or directory"` | `FOCALBOARD_DBCONFIG` 指的目录不存在，sqlite 不会自动建目录 | 改回 `./data/focalboard.db?_busy_timeout=5000`，并确认 `data/` 在 |
| `pthread_create failed: Operation not permitted` | 宿主机 Docker 太旧，libseccomp 不认 `clone3` | compose 里保留 `security_opt: [seccomp:unconfined]`（本包已带，别删） |
| `exec format error` | 架构不对（ARM 跑 amd64 镜像） | 见 9.7 |
| `no such image` | 镜像没导入 | 回第 3 步 `docker load` |

> 容器内是 **root** 运行，所以正常不会出现“数据库权限不足”。
> 真遇到 `permission denied`，基本是 `data/` 放在 NFS / 只读盘上，或者你手动改过 `user:`。

> 语录文件不存在**不会**让容器退出，也不会报错——它只在 `GET /api/v2/top-bar` 时按需读取，
> 读不到就返回空列表。别把“顶栏没内容”当成启动失败。

### 9.3 容器 Up 但页面打不开

按这顺序查：

```bash
# 1) 容器内部通不通（镜像里没有 curl/wget，用 bash 的 /dev/tcp 探测）
docker exec focalboard-lan bash -c 'echo > /dev/tcp/127.0.0.1/8088 && echo 容器内端口通'

# 2) 端口映射对不对
docker port focalboard-lan

# 3) 宿主机通不通
curl -v http://127.0.0.1:8088/ 2>&1 | head -10
```

| 现象 | 原因 |
| --- | --- |
| 容器内不通 | 应用没起来，看 9.2 的日志 |
| 容器内通、宿主机不通 | `ports` 与 `FOCALBOARD_PORT` 不一致 |
| 宿主机通、别的机器不通 | 防火墙 / 安全组（第 7 节） |
| 全是 `localhost` 通，`IP` 不通 | `FOCALBOARD_LOCALONLY` 被设成了 `"true"` |

### 9.4 语录 / 顶栏不显示

```bash
docker logs focalboard-lan 2>&1 | grep -o 'TopBarEnabled:[a-z]*'     # 要 true
docker exec focalboard-lan ls -l /opt/focalboard/conf/                # 文件要在
docker exec focalboard-lan head -2 /opt/focalboard/conf/quotes.txt    # 内容要能读
```

顶栏只在**看板页面内**出现；语录格式必须是 `[闲]` / `[忙]` 分段，行长别超过 256 KB。

三条容易白折腾的点（都实测过）：

1. **别用 `curl /api/v2/top-bar` 验**。这个接口要登录态，未登录直接返回
   `400 {"error":"checkCSRFToken FAILED"}`——不是坏了，是没带会话。要验就在浏览器里登录后看页面顶部。
2. **语录文件读不到不会报错**。日志里只会出现 `TopBarQuotesFile:/路径`，不会提示文件缺失；
   顶栏就是空的。所以必须用上面第 3 条 `head` 亲手确认容器内读得到。
3. **改完语录不用重启**。程序每次请求都重新读文件；如果你改了没变化，先确认改的是宿主机
   `conf/quotes.txt` 而不是别的路径（`docker exec ... head` 看的就是容器内实际内容）。

### 9.5 注册完进不去 / 卡在“加入看板”

这是**旧版本**的已知问题，第三版起已修（本包是第四版，天生带着）。确认你导入的是新版：

```bash
docker images | grep focalboard       # Image ID 应该是 c3ca048ea0a8
```

对不上说明还在用旧镜像，`docker load` 新包后 `docker compose up -d`。

### 9.6 数据目录没出现

方案 A 下 `./data` 是容器首次启动时才创建的。容器没起来 → 目录就不会有，先解决 9.2。
方案 B 用 `docker volume ls | grep focalboard` 查，而不是看目录。

### 9.7 ARM 机器（aarch64 / Apple M 系列）

本镜像是 `linux/amd64`，ARM 上要么走模拟（慢），要么自己重建：

```bash
# 有 Docker Desktop 的 Mac：直接跑，会自动用 qemu 模拟（慢但能用）
# Linux ARM 服务器：需要装 binfmt
docker run --privileged --rm tonistiigi/binfmt --install amd64
docker compose up -d
```

正式用建议按附录 C 在 ARM 机器上重建一份原生镜像。

### 附录 C：从源码重建镜像

```bash
cd 源码目录/focalboard-docker
docker build -t focalboard-lan:8.0.0-leave .
docker save focalboard-lan:8.0.0-leave focalboard-lan:8.0.0 | gzip -6 > focalboard-lan-8.0.0-leave.tar.gz
```

原版 Dockerfile 在纯国内网络下构建会失败，本包用的是打了**两处**最小修改的版本：

1. **构建阶段删掉 `apt-get install gcc libc6-dev`** —— 基础镜像 `golang:1.21.13-bookworm` 自带 gcc 12.2 + libc6-dev，
   再装是冗余；且该镜像的 `debian-archive-keyring` 已过期，`apt-get update` 会因
   `NO_PUBKEY … The repository is not signed` 中断。
2. **运行阶段的 `apt-get install ca-certificates tzdata` 改为从构建阶段拷入** ——
   `deb.debian.org` 国内不可达；换国内源后又卡在“运行镜像没有根证书 → https 校验失败 → 装不进去”的死循环：

   ```dockerfile
   COPY --from=build /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/ca-certificates.crt
   COPY --from=build /usr/share/zoneinfo/ /usr/share/zoneinfo/
   ```

   两个镜像同为 Debian 12，效果等价，构建不再依赖外网 apt。

Go 参数保持原样：`-tags "json1 sqlite3"`、`CGO_ENABLED=1`、`Edition=dev`，依赖走 `GOPROXY=https://goproxy.cn,direct`。
首次构建约 8~10 分钟（Go 编译 + sqlite3 的 C 编译占大头）。

### 附录 G：假勤版的上线注意（出网 & 新接口）

第四版多了两块要“吃网络”的能力，部署前务必知道：

**1. 节假日 / 节气数据需要容器能出网**

- 数据源（按顺序尝试）：`fastly.jsdelivr.net` → `cdn.jsdelivr.net` → `raw.githubusercontent.com`，
  抓 `NateScarlet/holiday-cn` 的年度 JSON
- 缓存文件：`data/holidays/{年份}.json`（落在数据卷里，**备份会一并带走**），每 3 天刷新一次
- **抓不到不会崩**：本版已修“空缓存”bug，抓取失败时继续用旧缓存，只是日历上没有节假日/节气标记
- 实测（测试环境）：三个源全部 `200`，容器起来后 `data/holidays/2026.json` 自动生成（3496 字节）

验证命令：

```bash
docker exec focalboard-lan ls -l /opt/focalboard/data/holidays
```

**期望**：能看到 `<年份>.json`。没有这个目录，说明容器出网被拦。

**2. 新增接口（都要登录态，未登录返回 400，不是坏了）**

| 接口 | 用途 |
| --- | --- |
| `GET /api/v2/leaves/summary` | 假勤汇总 |
| `POST /api/v2/leaves/records` | 新增一条假勤记录 |
| `DELETE /api/v2/leaves/records/{id}` | 删除记录 |
| `PUT /api/v2/leaves/settings` | 改清零规则等设置 |
| `GET /api/v2/leaves/export` | 导出 txt |
| `GET /api/v2/top-bar/calendar` | 顶栏日历 |
| `GET /api/v2/top-bar/lunar` | 全年农历 + 24 节气 |

用 `curl` 直接打会得到 `400 {"error":"checkCSRFToken FAILED"}`——**400 就是“路由存在但没带会话”**，
404 才是这版没装对。要验就在浏览器登录后点开假勤面板。

**3. 备份范围变了**

以前只要备 `data/` 里的 `focalboard.db` + `files/`，现在多一个 `data/holidays/`。
第 8.3 节的备份命令是整目录打包，**不用改**，会自动带上。
